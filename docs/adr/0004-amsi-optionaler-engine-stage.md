# AMSI als optionaler Engine-Stage, nie als Pflicht

Datum: 2025-09-27 (initial), 2026-10-05 (F5-Bridge-Bau nachgezogen)

AMSI-Scanning läuft nicht in der Aspire/Linux-Topologie (Aspire supportet keine Windows-Container; MCR-Images enthalten keinen AMSI-Provider). Die `AmsiScanBridge` (.NET-Worker auf Windows-Host) ist daher ein optionales Deployment-Profil, kein Bestandteil des Standard-Deployments. Standard ist die Linux-Baseline (ClamAV + YARA + Heuristik). Der Message-Contract ist engine-neutral mit Degradation: AMSI-Ausfall/Timeout erzeugt `Inconclusive` und erzwingt Review — niemals `Clean`. Begründung: Endpoint-AV auf den Clients ist eine zweite Kontrollinstanz, aber die Signier-Entscheidung fällt am Gate; Kunden mit höherem Schutzbedarf aktivieren die Bridge explizit. Die Semantik `Baseline-Clean ≠ Endpoint-AV-Clean` ist dokumentationspflichtig.

**Transport:** Die Brücke wird per HTTP angesprochen, nicht per RabbitMQ. Der WorkerService schickt die Datei-Bytes per `POST /scan` mit Header `X-Content-Name` (für AMSI contentName); die Antwort folgt dem Vertrag `AMSI_RESULT:0` (Clean) bzw. `AMSI_RESULT:1:<Detectionsname>` (Detected). Der HTTP-Pfad wurde gegenüber der initialen Annahme "RabbitMQ-Transport" korrigiert (Security-Review IF-10-Revision): die Brücke läuft auf einem dedizierten Host, RabbitMQ würde sie in der Saga-Sicht zu einem zweiten Konsumenten machen — HTTP auf Loopback ist die saubere Schnittstellentrennung.

**Authentisierung:** Shared-Secret im Header `X-Amsi-Bridge-Token` (F5-Beschluss). Beide Enden (WorkerService-Client, Brücke) erhalten denselben Wert als Aspire-Parameter `Parameters:amsi-bridge-token`. Die Brücke antwortet bei fehlendem/falschem Token mit 401 ohne AMSI-Aufruf — die Verdict-Policy verdichtet das als `EngineState.Failed` und damit als AMSI-Ausfall (Inconclusive-Pfad). mTLS wurde erwogen, aber verworfen: ein einzelner interner HTTP-Endpunkt auf einem dedizierten Host braucht keine PKI; das Shared-Secret ist über Aspire-Parameter/Umgebungsvariable versorgt (REQ-24, TM-12). Host-Grenze und TLS am Loopback sind die strukturelle Härtung.

Considered Options: AMSI als Pflicht-Stage (scheitert technisch an der Topologie), AMSI ganz streichen (schwächt den Clean-Verdict, Verlagerung der Kontrolle an den Endpunkt). Transport RabbitMQ (verworfen — HTTP auf Loopback trennt die Brücke sauber von der Saga-Konsumenten-Sicht). AuthN mTLS (verworfen — PKI-Overhead ohne Sicherheitsgewinn gegenüber Shared-Secret auf internem Loopback).
